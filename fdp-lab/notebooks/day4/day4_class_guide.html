Environment Architecture

Why Do We Use Docker for Big Data Labs?

Without Docker (Local Install)

  • Installing Java, Hadoop, Spark, and Kafka manually on Windows takes 1 full day.
  • JAVA_HOME, winutils.exe, and port conflicts break setups.
  • Small version mismatches (e.g., Spark 3.5 needing Scala 2.12 Kafka JARs) cause runtime errors.

With Docker Containers

  • Every PC runs the exact same Linux environment.
  • Spark 3.5.1, Kafka 3.8.0, Python, and connector JARs are pre-installed.
  • One command starts the lab; one command stops it cleanly without cluttering Windows.
Check Your Containers: Run docker ps — you should see two running containers: lab (Jupyter + Spark) and kafka (Broker).
Motivation

Real-World Scenario: EV Charging Stations

Imagine 1,000 EV Charging Stations sending live data every second (voltage, current, temperature, kWh). Multiple teams need this data at the same time:

  • Alert Service: Needs instant alerts if charger temp > 70°C (< 2 seconds).
  • Billing Service: Needs every kWh reading to bill customers accurately.
  • AI/ML Pipeline: Needs historical logs to predict charger failures.

Connecting chargers directly to all 3 systems creates point-to-point chaos: if Billing crashes for 10 minutes, revenue data is lost; peak traffic crashes the database.

Core Concept

What Is Apache Kafka?

Apache Kafka is a distributed event streaming server (written in Java/Scala) that acts as a durable, high-speed Central Digital Post Office.

  • EV Chargers send events once to Kafka.
  • Kafka writes events sequentially to disk in strict order.
  • Alert, Billing, and ML teams read from Kafka independently at their own speed.

Under the Hood

How Kafka Handles 10,000+ Stations Without Crashing

Performance & Storage

  • Strictly Append-Only: No UPDATE or DELETE. No SQL tables inside Kafka—only raw bytes (key + value).
  • OS Page Cache: Keeps JVM Heap tiny; Linux caches recent disk blocks in RAM automatically.
  • Zero-Copy: Sends bytes straight from disk cache to network card.

Connectivity & Security

  • Binary TCP (Port 9092): 10x–50x faster than HTTP. Producers use tiny 5ms micro-batches (linger.ms) for speed.
  • IoT Edge (MQTT): Chargers speak MQTT → Kafka Connect bridges to Kafka.
  • Security: TLS encryption, SASL/OAuth2 auth, ACLs.
Building Block #1

Kafka Topics: Organizing Your Event Streams

A Topic is a named feed or category where similar events live—just like a table in a database or a folder on disk. We separate streams by purpose so consumers only subscribe to what they need (e.g., station-telemetry, billing-events, error-alerts).

Option A: Create Topic via Kafka CLI

docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --create --if-not-exists \
  --topic station-telemetry \
  --partitions 3 \
  --bootstrap-server localhost:9092

Option B: Create Topic via Python

from kafka.admin import KafkaAdminClient, NewTopic

admin = KafkaAdminClient(bootstrap_servers="kafka:29092")
topic = NewTopic(name="station-telemetry",
                 num_partitions=3, replication_factor=1)
admin.create_topics([topic])
Flag / FunctionPurpose
--create --topic station-telemetryRegisters a new named stream inside the Kafka broker.
--partitions 3 / num_partitions=3Splits the topic into 3 parallel log files for scaling.
--bootstrap-serverAddress of any Kafka broker to discover the cluster.
--describe / --listInspects existing topics, partition leaders, and replication.
Building Block #2

Kafka Producers: Sending Events & Scaling Writes

A Producer is any external application (an EV charger gateway, web backend, or Python script using kafka-python) that pushes events into a Kafka Topic.

Python Producer Code (01_producer_ev.py)

from kafka import KafkaProducer
import json

producer = KafkaProducer(
    bootstrap_servers="kafka:29092",
    key_serializer=lambda k: k.encode("utf-8"),
    value_serializer=lambda v: json.dumps(v).encode("utf-8")
)

event = {"station_id": "S101", "temp_c": 74.2, "kwh": 2.1}
meta = producer.send("station-telemetry",
                     key="S101", value=event).get(timeout=10)
print(f"Sent to partition={meta.partition}, offset={meta.offset}")

Producer Scalability: 1 vs. Many

  • Single Producer: Good for testing or a single gateway.
  • Multiple Producers: 1,000 EV stations can all write to the same topic simultaneously without locking each other!
  • Tuning Speed: batch.size & linger_ms=5 group tiny events into one compressed TCP packet.
  • Durability (acks): acks=1 (leader confirms) vs acks="all" (zero data loss).
Function / ParameterPurpose
KafkaProducer(bootstrap_servers=...)Opens a persistent binary TCP connection to the Kafka broker.
key_serializer / value_serializerConverts Python strings/dicts into raw UTF-8 JSON bytes for Kafka.
producer.send(topic, key=..., value=...)Pushes the event asynchronously to the partition matching hash(key).
Building Block #3

Partitions, Offsets & Why the Hash Formula Matters

Kafka does not auto-create one partition per station. You choose the partition count, and Kafka routes keyed messages using: Partition = hash(key) % num_partitions.

Topic: "station-telemetry" (3 Partitions) ──────────────────────────────────────────────────────────────────────────────── Partition 0 (S101, S104...): HEAD (Oldest) TAIL (Writes) [ Offset 0 ] ──▶ [ Offset 1 ] ──▶ [ Offset 2 ] ◀── Producer appends Offset 3 {"id":"S101", {"id":"S101", {"id":"S101", "temp":42} "temp":44} "temp":72} Partition 1 (S102, S105...): [ Offset 0 ] ──▶ [ Offset 1 ] ◀── Producer appends Partition 2 (S103, S106...): [ Offset 0 ] ◀── Producer appends

Why Use This Hash Formula?

  • Guaranteed Order: All events with key="S101" always hit Partition 0 in exact time order.
  • No Key (key=None): Kafka spreads events Round-Robin across all partitions (max write speed, no per-station order).

How Many Partitions Should I Pick?

  • Partitions determine your maximum parallelism!
  • Rule: Max Parallel Consumers = Number of Partitions.
  • Small lab: 3. Production: 12–50 (too many = extra file handles/RAM overhead).
Building Block #4

Kafka Consumers & Consumer Groups

A Consumer pulls events from partitions using an internal poll loop and remembers its position using an Offset bookmark.

Python Consumer Code (02_consumer_group.py)

from kafka import KafkaConsumer
import json

consumer = KafkaConsumer(
    "station-telemetry",
    bootstrap_servers="kafka:29092",
    group_id="alert-team",
    auto_offset_reset="earliest",
    value_deserializer=lambda v: json.loads(v.decode("utf-8"))
)

for msg in consumer:
    print(f"P{msg.partition} Off={msg.offset}: {msg.value}")

Consumer Group Rules

  • Different Groups (alert-team vs billing-team): Separate offset bookmarks → both read 100% of messages.
  • Same Group (3 consumers in alert-team): Partitions split among them!
  • 1 Partition = 1 Consumer max inside one group (a 4th consumer on 3 partitions sits idle).
Function / ParameterPurpose
group_id="alert-team"Identifies which consumer team this worker belongs to for load balancing.
auto_offset_reset="earliest"If no saved offset exists, starts reading from Head (Offset 0) instead of Tail.
for msg in consumer:Continuously polls Kafka for new batches and auto-commits offsets.

Kafka + Spark

Who Runs Where? & Spark Structured Streaming

Spark IS the Consumer! You do not run a Python consumer in front of Spark — Spark connects directly to Kafka and treats the stream as an Unbounded SQL Table.

Spark Streaming FunctionPurpose
spark.readStream.format("kafka")Connects Spark directly to Kafka (kafka:29092) as a continuous stream.
from_json(col("value").cast("string"), schema)Parses raw Kafka JSON bytes into typed SQL columns (station_id, temp_c).
withWatermark("ts", "10 seconds")Handles late-arriving IoT events before closing a time window.
groupBy(window(col("ts"), "10 seconds"), ...)Computes rolling metrics (e.g., avg temperature per station every 10s).
writeStream.outputMode("append" | "update")Outputs new rows (append) or updated aggregations (update) with checkpointing.

Beyond EV Charging

How to Design Any New Scenario + 10 Real-World Examples

4-Step Blueprint for Any New Streaming Scenario: 1. Name your Topic & Partition count → 2. Pick the Partition Key (for ordering) → 3. Define the Producer JSON → 4. Write the Spark Filter / Window logic.

10 Industry Applications Using Apache Kafka

1. Ride-Sharing (Uber/Ola): Driver GPS pings every 3s (Key: driver_id) → live ETA & surge pricing.
2. UPI & Banking Fraud: Card/UPI swipes (Key: account_id) → block impossible geo-jumps in < 1s.
3. Food Delivery (Swiggy/Zomato): Order state + rider GPS → live map updates & kitchen alerts.
4. OTT Streaming (Netflix): Play/pause/buffer events → adaptive bitrate & live recommendations.
5. Stock Market Ticks: NSE/BSE price ticks (Key: symbol) → 1-min candlestick windows.
6. Hospital ICU Monitoring: Heart rate & SpO2 sensors (Key: patient_id) → instant nurse alerts.
7. Smart Power Grids: Smart meter kW readings → peak load balancing & outage detection.
8. E-Commerce Inventory: Clickstream + checkout events → prevent overselling flash-sale stock.
9. Telecom 5G Towers: Cell tower signal & drop logs → auto-detect failing hardware.
10. Fleet & Cold-Chain Logistics: Refrigerated truck temp sensors → alert if vaccine/food warms up.
