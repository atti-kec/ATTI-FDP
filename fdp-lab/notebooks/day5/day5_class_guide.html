Introduction to ML for Big Data

Why Not Just Use Python Scikit-Learn?

Yesterday we streamed live EV telemetry with Kafka. Over a year, 1,000 stations generate 500 GB+ of history. If we try loading that with Pandas & Scikit-Learn:

  • Single-PC RAM Limit: Pandas loads the whole table into one machine's memory → instant MemoryError (OOM) crash!
  • Single-Core Bottleneck: Standard Scikit-Learn steps often leave extra CPU cores idle.
FeatureScikit-Learn (sklearn)Spark MLlib (pyspark.ml)
ExecutionSingle machine RAMDistributed Cluster (1 to 1,000+ PCs)
Data FormatPandas DataFrame / NumPy arraysSpark DataFrame (distributed table)
Streaming LinkNeeds manual REST/FastAPI wrapperNative! Loads directly inside Day 4's Kafka stream

Architecture Fundamentals

How Does a "Distributed Cluster" Run on One 8 GB Laptop?

Cloud Cluster vs. Local Mode

  • Cloud Cluster: 1 Manager (Driver) + 10 Worker PCs (Executors).
  • Local Mode (.master("local[*]")): Spark turns your single laptop into a mini-cluster!
  • Does 50 GB crash 8 GB RAM? No! Spark slices files into Partitions (chunks), processes chunks in RAM, and safely spills excess to disk.

1 CPU vs. Cores vs. vCPUs

  • Inside 1 physical CPU chip are 4–8 hardware Cores (mini-brains).
  • Each core splits into 2 vCPUs (threads) — e.g., Docker sees 8 vCPUs.
  • The * in local[*] tells Spark: Use ALL available vCPUs in parallel!
Legacy vs. Modern Spark ML: Older Spark 1.x used pyspark.mllib (RDD-based). Modern Spark uses pyspark.ml (DataFrame + Pipeline API). Always use pyspark.ml!
Step 1 of ML Pipeline

Data Preprocessing: Cleaning Messy EV Sensor Logs

A Spark DataFrame is a 2D table with named columns and rows (like an Excel sheet or MySQL table, but sliced across CPU cores). Real IoT logs always arrive messy:

1. Remove Faulty Outliers

Drop impossible sensor readings (like voltage = -999):

clean_df = df.filter(col("voltage") > 0)

2. Drop vs. Impute Nulls

Never delete healthy rows just because 1 sensor dropped a reading! Use Imputer to fill missing values with the column mean/median.

3. Train / Test Split

Always hide 20% of data (Train/Test Split) to test fairly and avoid overfitting:

train_df, test_df = clean_df.randomSplit(
    [0.8, 0.2], seed=42
)

seed=42 guarantees everyone in class gets the exact same split.

Step 2 of ML Pipeline

Feature Engineering: Formatting Data for Spark MLlib

Unlike Scikit-Learn (where you pass multiple columns directly), every Spark MLlib algorithm expects ONE single column named features containing a dense array (Vector) of numbers!

Raw Columns After VectorAssembler ┌──────────┬─────────┬─────────────┬────────┐ ┌─────────────────────────┬───────┐ │station_id│ voltage │ current_amp │ temp_c │ ───▶ │ features (Single Vector)│ label │ ├──────────┼─────────┼─────────────┼────────┤ ├─────────────────────────┼───────┤ │ "S101" │ 238.5 │ 28.0 │ 74.2 │ │ [0.0, 238.5, 28.0, 74.2]│ 1.0 │ └──────────┴─────────┴─────────────┴────────┘ └─────────────────────────┴───────┘
Spark Feature TransformerWhat It Does
StringIndexerConverts text labels ("S101", "S102") into numeric IDs (0.0, 1.0). Use handleInvalid="keep" for new stations!
OneHotEncoderPrevents the model from thinking Station 2 is "twice as big" as Station 1 (turns index into binary flags [1,0,0]).
VectorAssemblerPacks all numeric input columns into one single features Vector column.
StandardScalerScales values (mean=0, std=1) so large numbers (voltage ~230) don't overpower small numbers (kWh ~2.0).
Interactive Lab #1

Chaining Everything with Pipeline

Instead of manually repeating cleaning, indexing, assembling, and scaling on both training data and live streaming data, wrap every step inside one Pipeline:

from pyspark.ml import Pipeline

pipeline = Pipeline(stages=[imputer, indexer, assembler, scaler])
fitted_pipeline = pipeline.fit(clean_df)       # Learns means & scaling stats
transformed_df  = fitted_pipeline.transform(clean_df)  # Applies them!

Task #1: Classification

Classification: Predicting EV Charger Faults (0 vs 1)

We train two classifiers on 500 EV sessions to detect overheating faults based on voltage, current, temperature, and kWh:

Logistic Regression

  • Fast linear boundary separating Fault (1) vs Normal (0).
  • Outputs both prediction (0/1) and probability (e.g., 92% chance of fault).
  • Great baseline model on huge datasets!

Random Forest Classifier

  • Builds an ensemble of Decision Trees (numTrees=30) and takes a majority vote.
  • Captures non-linear rules like "temp > 68 AND current > 22" automatically!
from pyspark.ml.classification import LogisticRegression, RandomForestClassifier

rf = RandomForestClassifier(featuresCol="features", labelCol="label", numTrees=30, maxDepth=5)
rf_pipeline = Pipeline(stages=[indexer, assembler, scaler, rf])
rf_model = rf_pipeline.fit(train_df)
predictions = rf_model.transform(test_df)

Task #2: Regression & Lab #3

Regression: Predicting Continuous Values (kWh / Cost)

When your target is a continuous number (like energy consumed in kwh, ride fare, or stock price), we use Regression.

Spark LinearRegression

from pyspark.ml.regression import LinearRegression
from pyspark.ml.evaluation import RegressionEvaluator

lr = LinearRegression(
    featuresCol="features",
    labelCol="kwh",
    maxIter=20,
    regParam=0.01
)
model = Pipeline(stages=[assembler, scaler, lr]).fit(train_df)

Regression Metrics Explained

  • RMSE: Average error in the same unit (kWh), penalizing big misses heavily. Lower is better.
  • MAE: Simple average absolute error.
  • R² (R-Squared): How much pattern the model explains (0.0 to 1.0; closer to 1.0 is better).

Task #3: Clustering & Lab #4

Clustering: Finding Hidden Groups Without Labels

What if your dataset has NO label column? K-Means Clustering discovers natural groups (e.g., Light, Normal, and Peak Stress charging sessions) automatically.

K-Means Pipeline Code

from pyspark.ml.clustering import KMeans
from pyspark.ml.evaluation import ClusteringEvaluator

kmeans = KMeans(featuresCol="features", k=3, seed=42)
model = Pipeline(stages=[assembler, scaler, kmeans]).fit(df)
clustered = model.transform(df)

score = ClusteringEvaluator().evaluate(clustered)

Evaluating Clusters

  • Important: Always run StandardScaler before K-Means because K-Means uses Euclidean distance!
  • Silhouette Score ranges from -1 to +1. Values near +1 mean clusters are tight and well-separated.
  • Use the Elbow Method to pick the best k.
